agent-hook entry point

We already have a neutral AgentEvent boundary. The next choice is where external hook payloads enter the app.

pet reaction
A

Local HTTP hook receiver

Run a small local endpoint. agent-hook sends POST payloads, the playground subscribes or polls translated AgentEvents.

Good

  • Closest to real integration
  • Works outside the browser
  • Easy to test with curl

Cost

  • Needs a tiny dev server process
  • Requires payload validation
B

Browser-only hook simulator

Add a textarea/control panel in the playground that accepts agent-hook-shaped JSON and maps it into AgentEvent.

Good

  • Fastest visual iteration
  • No backend process
  • Great for mapping design

Cost

  • Not real hook transport
  • Still needs a later receiver
C

Desktop bridge first

Design the adapter as if Tauri/desktop receives hooks and forwards AgentEvents into the renderer.

Good

  • Matches eventual product shape
  • Clean desktop boundary

Cost

  • Too heavy for the browser playground slice
  • More moving parts now

My recommendation: A if you want real integration now, B if we need to finalize payload mapping first.
