# Agent-Hook Narration for Pet Status Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the pet's status card show a real one-line narration of what the
agent is actually doing, generated by a Claude Code agent-based hook at each
status transition (working/waiting/completed), instead of the canned label
text it shows today.

**Architecture:** Three Hook Bridge plugin hooks (`UserPromptSubmit`,
`Notification`, `Stop`) switch from `type:"command"` (raw passthrough) to
`type:"agent"` (spawns a subagent that writes a one-line narration, then
forwards it). The forward script gains a `summary` mode that POSTs the
narration text to the existing local ingress. The Claude-hook adapter already
reads a `summary` field, so no change is needed there. The one required bug
fix is in `packages/pet-engine/src/features/behavior/systems.ts`, which
currently discards `summary` by hardcoding `message: null` when writing
`AgentChannelState` — without this fix, nothing generated upstream would ever
reach the screen.

**Tech Stack:** TypeScript (pet-engine ECS, Vitest), Bash (Hook Bridge plugin
scripts), Claude Code plugin hooks (`type:"agent"`), existing Tauri HTTP
ingress (unchanged).

## Global Constraints

- Claude Code plugin hooks only — Codex hooks (`codex-hooks.json`,
  `forward-codex`) are out of scope and must not be touched.
- Agent hooks must never block or fail the user's turn: `async: true`, and the
  hook must always return `{"ok": true, ...}` — narration only, never gating.
- `PreToolUse`/`PostToolUse` stay excluded from forwarding (unchanged,
  high-frequency/low-value per existing design).
- No new `AgentChannelSource` values — keep writing `source: "agent-task"` as
  today; no UI code branches on `source`, so introducing `"agent-hook"` here
  would be unused surface.
- The `run-hook.cmd` wrapper only forwards positional args `%2`-`%9` (8 args
  after the script name) — any new `forward` subcommand must fit within that.

```typescript
function setAgentTaskState(
  components: ComponentStore,
  id: string,
  status: "working" | "waiting" | "completed" | "failed",
  event: { at: number; summary?: string },
): void {
  components.setComponent(id, {
    type: "AgentTaskState",
    status,
    since: event.at,
    summary: event.summary,
  });
  components.setComponent(id, {
    type: "AgentChannelState",
    source: "agent-task",
    status,
    label: agentTaskChannelLabel(status),
    message: event.summary ?? null,
    updatedAt: event.at,
    expiresAt: null,
  });
}
```

`message: event.summary ?? null,`.)

### Task 2: Add a `summary` forward mode to the Hook Bridge plugin script

**Files:**
- Modify: `plugins/pets-driven/hooks/forward`

**Interfaces:**
- Consumes: existing `post()`, `json_escape()`, `self_check()` helpers already
  defined in this file.
- Produces: a new invocation shape,
  `forward summary "<hook_event_name>" "<text>"`, that later Task 3 references
  from `hooks.json` prompts. POSTs
  `{"hook_event_name":"<name>","cwd":"<$PWD>","summary":"<text>"}` to the same
  ingress URL as every other mode in this file.

- [ ] **Step 1: Add the failing self-check assertion**

In `plugins/pets-driven/hooks/forward`, extend the `self_check()` function
(the block that currently ends with the `hatch_body` escaping assertion) by
inserting this block right before the final `echo "self-check passed"` line:

```bash
  local summary
  summary="$(summary_body "Stop" 'He said "hi" and left')"
  case "$summary" in
    *'"hook_event_name":"Stop"'*) ;;
    *) echo "FAIL: missing hook_event_name in: $summary" >&2; exit 1 ;;
  esac
  case "$summary" in
    *'\\"hi\\"'*) ;;
    *) echo "FAIL: summary text not escaped: $summary" >&2; exit 1 ;;
  esac
```

- [ ] **Step 2: Run the self-check to verify it fails**

Run: `bash plugins/pets-driven/hooks/forward --self-check`
Expected: fails with `FAIL: missing hook_event_name in:` (or a shell error),
since `summary_body` does not exist yet.

- [ ] **Step 3: Implement `summary_body` and wire the `summary` case**

Add this function to `plugins/pets-driven/hooks/forward`, next to the
existing `attach_body`/`hatch_body` functions:

```bash
summary_body() {
  printf '{"hook_event_name":"%s","cwd":"%s","summary":"%s"}' \
    "$(json_escape "$1")" \
    "$(json_escape "$PWD")" \
    "$(json_escape "$2")"
}
```

Then add a `summary` case to the dispatcher (the `case "$1" in ... esac`
block), placed before the catch-all `*)` case:

```bash
  summary)
    shift
    post "$(summary_body "$@")"
    ;;
```

- [ ] **Step 4: Run the self-check to verify it passes**

Run: `bash plugins/pets-driven/hooks/forward --self-check`
Expected: `self-check passed`, exit code 0.

- [ ] **Step 5: Commit**

```bash

git commit -m "feat: add summary forward mode to Hook Bridge plugin"
```
